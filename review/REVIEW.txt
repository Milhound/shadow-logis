Archive identity

4c82756814763b20d717f51104f3d7ce9cf6023c68a2fe933241f2980ae50311

The archive holds a Clarion 5-era, 32-bit Intel Windows installation. Main
executable depends on C5RUNX/C5TPSX and Win32-specific UI, printing and report
modules. The archive also includes auxiliary programs, utilities, Windows
services, and older DOS/16-bit components. No application CLW/APP/DCT source was found,
including in the nested ZIP inventories. Bundled C++ source belongs to NSSM.

This prevents a conventional native recompile of the supplied program. The
implemented route is a native C++/Qt replacement over migrated data. Binary
inspection was read-only; none of the supplied EXEs was executed. REA's public
repository was reviewed as an optional disassembly aid but was not installed
or used as a runtime. Detailed binary hashes/imports are retained privately, outside the source distribution.

Storage design and checks
-------------------------
source_files preserves complete TPS files, hashes and decode status.
datasets preserves field/memo schemas and import counts.
records stores the legacy row identity, original bytes, searchable/editable
JSON values and a revision number. Numeric values remain strings to avoid
binary rounding of exact decimals. Arrays remain arrays. Windows-1252 text
is an explicit assumption; original bytes allow later correction.
memos preserves every joined memo byte sequence, including orphaned values.
documents preserves historical PDF bytes and hashes.
record_history retains prior JSON values for changed records in the same
transaction as each edit. A stale version fails rather than replacing changes.

Import verification read back every original row byte string and checked row
counts. Independent Python/sqlite3 verification then matched all 205 archived
files to source hashes, validated record extents/counts, memo counts, JSON and
SQLite integrity. Original source preservation does not prove correct active
row selection from TPS indexes. That still requires application reconciliation.

Version 0.10.0 entry assistance and calculations
-----------------------------------------------
User workflow review found that kilograms/pounds were repeated manual entries,
AWB charge and dimension fields were printable but inaccessible for editing,
and there was no selective way to pull updated shared shipment information.
The changes keep the shipment-first layout and add tools at the point of use.

Shipment and cargo-line weight pairs have explicit Manual, kg-to-lb and lb-to-kg
modes. Cargo-line CBM/CFT pairs have equivalent modes. Typing into a calculated
result switches to Manual; reselecting the mode resumes. Modes persist in native
JSON metadata. Native schema views allow fractional shipment and document header
weights, while original TPS schemas, source bytes and existing values are kept.
Conversions use the exact international pound/foot constants and checked rational
arithmetic, with two decimal places for weight and three for volume. No conversion
runs on old records without an explicit calculation mode.

AWB Dimensions / weight supports the user's three separate formulas:
  - cm3 / 6000 => kg
  - in3 / 166 => lb
  - CBM * 167 => kg (not the reciprocal of 6000)
The factor is editable and stored per document. Dimensions and counts have five
rows with explicit cargo-row assignment. Direct CBM has a volume per cargo row;
a new one-row AWB preloads its saved shipment CBM. Results convert to the cargo
weight unit. Dimension rounding (as entered / nearest / up) is separate from
chargeable weight rounding (up to 1 / 0.5 / 0.01). Automatic chargeable weight
uses max(gross, assigned dimensional weight), requiring complete piece coverage
for dimensions or positive CBM for an active row. Typing a chargeable override
disables that row's automatic weight only. The old sixth cargo/rating working
slot is excluded and preserved. CBM-mode PDFs show volume and dimensional weight
in the goods panel, suppressing inactive saved size rows without deleting them.
Physical volume calculations use bounded long-double arithmetic; monetary
calculations use checked integer decimal arithmetic and half-up cents per line.

Rates / charges exposes rates/classes, individual fee amounts, payment sides,
agent/carrier allocation, currency, minimum charge, AS AGREED, and summaries.
Line, weight-charge, fee-summary and grand-total calculations are independent.
Editing a result disables its calculation; toggles restore it. Imported rates
and amounts default to manual. Per-unit calculations accept ordinary N/Q/K or
blank classes, with explicit refusal for basic/minimum/ULD/special classes and
stored minimum charges. Tariff selection, weight-break optimization, valuation
rules and tax rules are not inferred. Fees must have valid payment/account
choices before automatic allocation. The single printed Other charges flag
requires a common side for automatic fee totals; mixed arrangements remain
manual. Preview and Store::save share calculation dependency order, including
post-reopen changes. Helper Apply modifies the editor only; Save is the write.

Use shipment details reviews current/proposed party, routing, reference and note
